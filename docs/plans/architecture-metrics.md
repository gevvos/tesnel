# Architecture Metrics — метрики компонентов по Роберту Мартину

## Идея

Автоматическая оценка архитектурного здоровья проекта на основе метрик из Clean Architecture. Tesnel уже строит полный граф зависимостей с разделением type-import и runtime-import — этого достаточно для расчёта всех метрик Мартина.

## Метрики

### Instability (I) — нестабильность

```
I = Fan-out / (Fan-in + Fan-out)
```

- **Fan-in** — количество входящих зависимостей (кто импортирует этот модуль)
- **Fan-out** — количество исходящих зависимостей (что импортирует этот модуль)
- **I = 0** — максимально стабильный (от него все зависят, он ни от кого)
- **I = 1** — максимально нестабильный (зависит от других, от него никто)

### Abstractness (A) — абстрактность

```
A = type-only exports / total exports
```

Tesnel уже различает `import type` и runtime import. Модуль с большой долей type-only экспортов — более абстрактный.

- **A = 0** — полностью конкретный (только runtime экспорты)
- **A = 1** — полностью абстрактный (только типы/интерфейсы)

### Distance from Main Sequence (D) — расстояние

```
D = |A + I - 1|
```

Главная последовательность (Main Sequence) — линия от (A=1, I=0) до (A=0, I=1). Идеальные компоненты лежат на ней. Чем дальше — тем хуже.

- **D = 0** — идеальный баланс
- **D → 1** — компонент в проблемной зоне

### Зоны проблем

| Зона | A | I | Проблема |
|------|---|---|----------|
| **Zone of Pain** | ≈0 | ≈0 | Конкретный + стабильный. Все зависят, трудно менять. Пример: утилиты без интерфейсов |
| **Zone of Uselessness** | ≈1 | ≈1 | Абстрактный + нестабильный. Никому не нужные абстракции |

## Уровень агрегации

Метрики считаются на уровне **директорий** (компонентов/модулей), не отдельных файлов:

```
src/
  components/    → I=0.7, A=0.1, D=0.2
  services/      → I=0.3, A=0.4, D=0.3
  utils/         → I=0.1, A=0.0, D=0.9  ← Zone of Pain
  types/         → I=0.9, A=1.0, D=0.1
```

Глубину агрегации выбирает пользователь (1 = top-level директории, 2 = вложенные и т.д.).

## Интеграция в tesnel

### CLI

```bash
# Вывести метрики в консоль
tesnel metrics ./src

# С ограничением глубины агрегации
tesnel metrics ./src --depth 2

# Порог для lint — фейл если D > 0.3
tesnel lint ./src --max-distance 0.3
```

### UI

- Новая вкладка/панель «Metrics»
- График A/I с линией Main Sequence
- Директории как точки на графике, размер = количество файлов
- Цвет: зелёный (D < 0.2), жёлтый (D < 0.5), красный (D ≥ 0.5)
- При клике на точку — детали: fan-in, fan-out, список зависимостей

### MCP

Новый tool `tesnel_get_metrics`:

```json
{
  "tool": "tesnel_get_metrics",
  "input": { "depth": 1 },
  "output": {
    "modules": [
      {
        "path": "src/components",
        "files": 12,
        "fanIn": 8,
        "fanOut": 15,
        "instability": 0.65,
        "abstractness": 0.12,
        "distance": 0.23
      }
    ]
  }
}
```

### JSON output

Новая секция `metrics` в `output.json`:

```json
{
  "metrics": {
    "modules": [...],
    "summary": {
      "avgDistance": 0.28,
      "maxDistance": 0.9,
      "modulesInPainZone": 1,
      "modulesInUselessnessZone": 0
    }
  }
}
```
